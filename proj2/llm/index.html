    PART 1.1Convolutions from Scratch!

    A 2D convolution slides a flipped kernel over the image and takes a weighted sum at every position:

    $$ (f * h)[i,j] \;=\; \sum_{m}\sum_{n} f[i-m,\; j-n]\; h[m,n] \;=\; \sum_{m}\sum_{n} f[i+m,\; j+n]\; \underbrace{h[-m,-n]}_{\text{flipped kernel}} $$

    The minus signs are the difference between convolution and correlation. For a symmetric kernel like a box or a Gaussian they are the same thing. For an antisymmetric one like $D_x = [1,\,-1]$ the flip changes the sign of the answer, which is why every implementation below starts with kernel[::-1, ::-1].

    Five ways to slide a kernel

    All five share one preparation step: flip the kernel, pad the image, and work out the output size. Padding is written by hand (no np.pad) with four boundary rules. _pads decides how much padding goes on each side so the output lines up exactly with SciPy's 'full', 'same' and 'valid' modes, including the fiddly off-by-one for even-sized kernels (more on that below).

    slop/conv.py · pad2d()
    def pad2d(img: np.ndarray, top: int, bottom: int, left: int, right: int,
          boundary: str = "zero") -> np.ndarray:
    """Pad a 2D array by hand (np.pad is avoided on purpose; this is the from-scratch section)."""
    H, W = img.shape
    out = np.zeros((H + top + bottom, W + left + right), dtype=np.float64)
    out[top:top + H, left:left + W] = img
    if boundary == "zero":
        return out

    # Build a source index for every padded row / column, then gather once.
    def index_map(n: int, before: int, after: int) -> np.ndarray:
        idx = np.arange(-before, n + after)
        if boundary == "edge":
            return np.clip(idx, 0, n - 1)
        if boundary == "wrap":
            return idx % n
        if boundary == "reflect":  # symmetric: ... 2 1 0 | 0 1 2 ... | n-1 n-2 ...
            period = 2 * n
            m = idx % period
            return np.where(m < n, m, period - 1 - m)
        raise ValueError(f"unknown boundary {boundary!r}")

    rows = index_map(H, top, bottom)
    cols = index_map(W, left, right)
    return img[rows[:, None], cols[None, :]]
    slop/conv.py · _pads()
    def _pads(kh: int, kw: int, mode: str) -> tuple[int, int, int, int]:
    """(top, bottom, left, right) padding that reproduces scipy's output alignment."""
    if mode == "full":
        return kh - 1, kh - 1, kw - 1, kw - 1
    if mode == "same":
        # scipy crops the 'full' output starting at (k-1)//2
        oh, ow = (kh - 1) // 2, (kw - 1) // 2
        return kh - 1 - oh, oh, kw - 1 - ow, ow
    if mode == "valid":
        return 0, 0, 0, 0
    raise ValueError(f"unknown mode {mode!r}")

    1 · Four loops: the definition, typed out

    Two loops over output pixels, two over kernel taps, and one multiply-add in the middle. Nothing is hidden and nothing is fast.

    slop/conv.py · conv2d_4loops()
    def conv2d_4loops(img, kernel, mode="same", boundary="zero"):
    """The most literal definition: loop over output pixels AND kernel taps."""
    P, kf, kh, kw, oh, ow = _prepare(img, kernel, mode, boundary)
    out = np.zeros((oh, ow))
    for i in range(oh):
        for j in range(ow):
            acc = 0.0
            for m in range(kh):
                for n in range(kw):
                    acc += P[i + m, j + n] * kf[m, n]
            out[i, j] = acc
    return out

    2 · Two loops over pixels

    Keep the pixel loops and let numpy do the kernel dot-product as one element-wise multiply and sum over a window.

    slop/conv.py · conv2d_2loops()
    def conv2d_2loops(img, kernel, mode="same", boundary="zero"):
    """Loop over output pixels; the kernel dot-product is one vectorised multiply-sum."""
    P, kf, kh, kw, oh, ow = _prepare(img, kernel, mode, boundary)
    out = np.zeros((oh, ow))
    for i in range(oh):
        for j in range(ow):
            out[i, j] = np.sum(P[i:i + kh, j:j + kw] * kf)
    return out

    3 · Two loops over taps, the underrated one

    The assignment says "two for loops" but doesn't say which two. If you loop over the $k_h \times k_w$ kernel taps instead of the $H\times W$ pixels, each iteration adds one shifted, scaled copy of the whole image. That's 81 Python iterations for a 9×9 box instead of 285,156. It computes the same sum in a different order and turns out to be the fastest spatial-domain method on this page, SciPy included.

    slop/conv.py · conv2d_2loops_taps()
    def conv2d_2loops_taps(img, kernel, mode="same", boundary="zero"):
    """The *other* way to use two loops: loop over the kh*kw kernel taps and add a
    shifted, scaled copy of the whole image for each one. Same maths, ~1000x fewer
    Python iterations for a normal-sized image."""
    P, kf, kh, kw, oh, ow = _prepare(img, kernel, mode, boundary)
    out = np.zeros((oh, ow))
    for m in range(kh):
        for n in range(kw):
            out += kf[m, n] * P[m:m + oh, n:n + ow]
    return out
    4 · Zero loops with a strided window view, and 5 · the FFT

    Strided einsum. as_strided builds a 4-D view of shape $(H, W, k_h, k_w)$ in which every window is a sub-array. Nothing is copied, only stride metadata. One einsum then contracts it against the flipped kernel. This is im2col without the memory bill.

    slop/conv.py · conv2d_strided()
    def conv2d_strided(img, kernel, mode="same", boundary="zero"):
    """im2col without copying: build a (oh, ow, kh, kw) window view with raw strides
    and contract it against the flipped kernel with einsum."""
    P, kf, kh, kw, oh, ow = _prepare(img, kernel, mode, boundary)
    s0, s1 = P.strides
    windows = np.lib.stride_tricks.as_strided(
        P, shape=(oh, ow, kh, kw), strides=(s0, s1, s0, s1), writeable=False)
    return np.einsum("ijmn,mn->ij", windows, kf, optimize=True)

    FFT. The convolution theorem, $\mathcal{F}\{f*h\} = \mathcal{F}\{f\}\cdot\mathcal{F}\{h\}$, turns the sum into a multiplication. Zero-pad both signals to the full output size so the circular convolution the FFT computes becomes a linear one, multiply the spectra, invert, and crop. The cost is $O(N\log N)$ however big the kernel is.

    slop/conv.py · conv2d_fft()
    def conv2d_fft(img, kernel, mode="same", boundary="zero"):
    """Convolution theorem: zero-pad both to the full size, multiply spectra, crop.
    Cost is O(N log N) regardless of kernel size -- the winner for big kernels."""
    img = np.asarray(img, dtype=np.float64)
    k = np.asarray(kernel, dtype=np.float64)
    kh, kw = k.shape
    H, W = img.shape
    if boundary != "zero":
        # emulate the boundary by padding explicitly, then take the 'valid' part of that
        t, b, l, r = _pads(kh, kw, mode)
        img = pad2d(img, t, b, l, r, boundary)
        mode = "valid"
        H, W = img.shape
    fh, fw = H + kh - 1, W + kw - 1
    # next fast length (powers of 2, 3, 5) keeps numpy's FFT happy
    fh2, fw2 = _fast_len(fh), _fast_len(fw)
    F = np.fft.rfft2(img, s=(fh2, fw2)) * np.fft.rfft2(k, s=(fh2, fw2))
    full = np.fft.irfft2(F, s=(fh2, fw2))[:fh, :fw]
    if mode == "full":
        return full
    if mode == "same":
        oh, ow = (kh - 1) // 2, (kw - 1) // 2
        orig_h, orig_w = H, W
        return full[oh:oh + orig_h, ow:ow + orig_w]
    return full[kh - 1:H, kw - 1:W]  # valid

    What the race says

    Python loops are the cost, not arithmetic. The 4-loop and 2-loop-over-pixels versions do the same number of multiplies as SciPy. They're 204× and 23× slower because every iteration goes through the interpreter. Dropping from 4 loops to 2 loops over pixels buys 9×. Swapping to 2 loops over taps buys 270× and edges out SciPy's compiled direct convolution.

    The FFT wins everywhere here, and it wins big once kernels get large: at 41×41 it is 79× faster than SciPy's direct method. scipy.signal.convolve2d always convolves directly, which is why scipy.signal.fftconvolve exists.

    The strided einsum has a cliff. It's competitive up to 9×9, then jumps ~50× at 15×15. I didn't profile it, but my suspicion is einsum's contraction strategy over a non-contiguous 4-D view: the windows overlap in memory, so a large-kernel view gets awful cache behaviour.

    Boundaries: what happens past the edge?

    'Same' output needs kernel-sized information from outside the image, so every implementation has to invent it. Below is the cameraman padded by 90 px with each rule; the pink outline is the real image.

    The even-kernel gotcha. A 9×9 box has a centre; $D_x = [1,-1]$ does not. SciPy's 'same' mode crops the 'full' result starting at index $\lfloor (k-1)/2 \rfloor = 0$ for $k=2$, so

    $$ (f * D_x)_{\text{same}}[i, j] = f[i,j] - f[i,j-1], $$

    a backward difference whose response sits on the right-hand pixel of each pair. Under zero padding, column 0 becomes $f[i,0] - 0$, which is the image itself. Measured on the cameraman, that column's mean absolute "derivative" is 0.56, against 0.00 with reflect padding. ('full' keeps both: shape [534, 535].) For that reason I use boundary='symm' for every derivative from 1.2 onward.

    PART 1.2Finite Difference Operator

    The smallest possible derivative: subtract a pixel from its neighbour. Convolving with $D_x = [1,\,-1]$ and $D_y = [1,\,-1]^\top$ gives the two partial derivatives, and together they make the gradient.

    $$ \nabla f = \begin{bmatrix} \partial f/\partial x \\ \partial f/\partial y \end{bmatrix} \approx \begin{bmatrix} f * D_x \\ f * D_y \end{bmatrix},\qquad \|\nabla f\| = \sqrt{(f*D_x)^2 + (f*D_y)^2} $$

    The magnitude is large wherever brightness changes quickly, which is at edges and, unfortunately, also at noise. I use scipy.signal.convolve2d(..., mode='same', boundary='symm') so the image border doesn't produce the fake column of edges from 1.1.

    Choosing the threshold

    The histogram explains why this is hard. The median gradient is 0.0055 while the maximum is 0.87. Almost every pixel sits in a huge pile of tiny gradients from sensor noise and grass, and real edges form a long thin tail. There's no clean valley to cut at.

    parts/p1_2_finite_diff.py · otsu()
    def otsu(values: np.ndarray, bins: int = 512) -> float:
    """Otsu's threshold by hand: maximise between-class variance over all histogram cuts."""
    hist, edges = np.histogram(values, bins=bins)
    p = hist / hist.sum()
    centers = (edges[:-1] + edges[1:]) / 2
    w0 = np.cumsum(p)                       # weight of the "below" class at each cut
    mu0_num = np.cumsum(p * centers)
    mu_total = mu0_num[-1]
    w1 = 1 - w0
    valid = (w0 > 0) & (w1 > 0)
    between = np.zeros_like(w0)
    between[valid] = (mu_total * w0[valid] - mu0_num[valid]) ** 2 / (w0[valid] * w1[valid])
    return float(edges[np.argmax(between) + 1])

    PART 1.3Derivative of Gaussian (DoG) Filter

    The finite-difference edges were noisy because differentiation amplifies high frequencies, and noise lives almost entirely in the high frequencies. The fix is to smooth first. I blur with a Gaussian $G_\sigma$ with $\sigma = 1.50$ px, whose kernel is 11×11 ($\pm 3\sigma$), and only then differentiate.

    The 2D Gaussian comes from cv2.getGaussianKernel, as suggested: a 1-D column $g$, and then $G = g\,g^\top$. The outer product works because the 2D Gaussian is separable, $e^{-(x^2+y^2)/2\sigma^2} = e^{-x^2/2\sigma^2}\,e^{-y^2/2\sigma^2}$.

    slop/filters.py · gaussian_2d()
    def gaussian_2d(sigma: float, ksize: int | None = None) -> np.ndarray:
    g = gaussian_1d(sigma, ksize)
    return g @ g.T  # outer product with its transpose

    Route 2: one convolution with a DoG filter

    Convolution is associative, $(f * G) * D_x = f * (G * D_x)$, so I can fold the derivative into the Gaussian once to get a derivative-of-Gaussian filter. After that, each image costs one convolution instead of two:

    parts/p1_3_dog.py · dog_route()
    def dog_route(img, sigma):
    """Route 2: fold the derivative into the Gaussian once, then convolve the image once."""
    G = gaussian_2d(sigma)
    dog_x = convolve2d(G, DX)                           # 'full': the DoG is one pixel wider
    dog_y = convolve2d(G, DY)
    gx = convolve2d(img, dog_x, mode="same", boundary="symm")
    gy = convolve2d(img, dog_y, mode="same", boundary="symm")
    return dog_x, dog_y, gx, gy

At a boundary, "reflect, then blur, then reflect the blurred image" could in principle differ from "reflect, then blur with the bigger kernel". The blur of a mirror-symmetric extension is itself mirror-symmetric, so padding the blurred image reproduces exactly what the one-shot DoG sees.

    Differences I see

    1 · The noise is gone. Isolated specks drop from 584 to 59, and on the lawn from 189 to 13. The Gaussian averages away pixel-level noise before the derivative can amplify it.

    2 · Edges are connected. The same outlines come out in 97 pieces instead of 674. The coat, the tripod legs and the skyline domes are unbroken curves, and even the faint domes survive, which no single finite-difference threshold could manage.

    3 · Edges are thicker and less precisely placed. Average width grows from 1.1 to 3.9 px, because the blur spreads each step over roughly $\pm\sigma$ pixels. That's the price of smoothing, and non-maximum suppression (below) gets it back.

    4 · The numbers shrink. Blurring a step lowers its peak slope by about $1/(\sqrt{2\pi}\,\sigma)$. That's why the right threshold falls from 0.26 to 0.050, and why Otsu's automatic cut (0.048) is now close to the value I picked by eye. Smoothing turns the histogram from "one mountain" into something Otsu can actually split.

    How much blur?

    $\sigma$ is the knob that trades noise against detail. Scrub through seven scales (the kernel is always $2\lceil 3\sigma \rceil + 1$ wide):

    At σ = 0.5 it's barely better than raw differences: blocky contours and a lawn full of fragments. From σ = 1 to 2 the result is clean, with facial features and the camera's details intact.     Extra: getting thin edges back (Canny, by hand)

    The DoG's thick edges come from thresholding a smooth ridge. Canny's fix has two parts. Non-maximum suppression keeps a pixel only if it's a local max across the edge, along the gradient. Hysteresis uses two thresholds: strong pixels seed edges, and weak pixels survive only if they connect to a strong one. The gradient direction is binned into four sectors with slope tests against $\tan 22.5° = \sqrt2 - 1$, an algebraic number, so no angle function is needed here either.

    parts/p1_3_dog.py · non_max_suppression()
    def non_max_suppression(gx, gy):
    """Keep a pixel only if it beats both neighbours along its gradient direction.
    The direction is binned into 4 sectors with slope comparisons, not angles."""
    mag = np.hypot(gx, gy)
    ax, ay = np.abs(gx), np.abs(gy)
    P = np.pad(mag, 1)
    c = P[1:-1, 1:-1]
    left, right = P[1:-1, :-2], P[1:-1, 2:]
    up, down = P[:-2, 1:-1], P[2:, 1:-1]
    ul, dr = P[:-2, :-2], P[2:, 2:]
    ur, dl = P[:-2, 2:], P[2:, :-2]
    horiz = ay <= TAN_22_5 * ax                       # gradient ~ along x: compare left/right
    vert = ax <= TAN_22_5 * ay                        # gradient ~ along y: compare up/down
    diag_main = ~horiz & ~vert & (gx * gy > 0)        # (+x, +y) direction (y points down)
    diag_anti = ~horiz & ~vert & (gx * gy <= 0)
    keep = np.zeros_like(mag, dtype=bool)

    PART 1 · BELLS & WHISTLESGradient Orientation in Colour

    The magnitude tells you how strong an edge is; the gradient's direction, $\theta = \operatorname{atan2}(g_y, g_x)$, tells you which way brightness increases. Direction is an angle, and angles wrap around, so it belongs on a colour wheel: hue is cyclic too.

    The catch is that I'm not allowed built-in angle functions. No np.arctan2, np.angle, math.atan or np.degrees. So I built the angle from scratch.

    Step 1 · An angle from adds and halvings: CORDIC

    CORDIC (Volder, 1959) is how pocket calculators and FPGAs compute arctangents without a multiplier. To find the angle of $(x, y)$, rotate the vector toward the $+x$ axis by a fixed sequence of shrinking angles $\alpha_i = \arctan 2^{-i}$ (45°, 26.6°, 14.0°, 7.1°, …), each time choosing the direction that moves $y$ toward 0, and add up the angles used:

    $$ \begin{aligned} d_i &= \operatorname{sign}(y_i) \\ x_{i+1} &= x_i + d_i\, y_i\, 2^{-i} \\ y_{i+1} &= y_i - d_i\, x_i\, 2^{-i} \\ \theta &\mathrel{+}= d_i\, \alpha_i \end{aligned} $$

    Each step is a rotation by $\pm\alpha_i$ (scaled by a constant that cancels, since only the angle matters). With $\tan\alpha_i = 2^{-i}$, a rotation needs only adds and multiplications by powers of two, and every iteration buys roughly one more bit of angle. Vectors in the left half-plane first get a ±90° swap, $(x,y)\to(\pm y, \mp x)$, because CORDIC alone only converges within ±99.7°.

    The table $\alpha_i$ needs arctangents, so I didn't cheat there either. Each entry comes from the Taylor series $\arctan x = x - x^3/3 + x^5/5 - \dots$, and $\pi$ comes from Machin's 1706 formula, $\pi/4 = 4\arctan\tfrac15 - \arctan\tfrac1{239}$. It lands within 8.9e-16 of np.pi, which is exact to the last bit of a float64.

    def cordic_atan2(y: np.ndarray, x: np.ndarray, iters: int = N_ITERS) -> np.ndarray:
    """Vectorised CORDIC atan2. Returns angles in (-pi, pi]."""
    x = np.asarray(x, dtype=np.float64).copy()
    y = np.asarray(y, dtype=np.float64).copy()
    theta = np.zeros_like(x)

    # Pre-rotate the left half-plane by +-90 degrees so CORDIC's +-99.9 degree range suffices.
    left = x < 0
    up = left & (y >= 0)
    down = left & (y < 0)
    x_up, y_up = y[up], -x[up]          # rotate by -90 deg
    x_dn, y_dn = -y[down], x[down]      # rotate by +90 deg
    x[up], y[up] = x_up, y_up
    x[down], y[down] = x_dn, y_dn
    theta[up] = PI / 2
    theta[down] = -PI / 2

    p = 1.0
    for i in range(iters):
        d = np.where(y > 0, 1.0, -1.0)   # which way to rotate to drive y -> 0
        x, y = x + d * y * p, y - d * x * p
        theta += d * ATAN_TABLE[i]
        p *= 0.5
    return theta

    def orientation_hsv(gx, gy, doubled=False, v_scale=None, gamma=0.8):

    Image rows grow downward, so I flip gy to measure angles counter-clockwise
    from +x with y pointing *up* (0 = gradient pointing right, 90 deg = up).

    Fun with Frequencies

    Everything from here on is about which frequencies an image contains and what happens when you boost, cut or swap them. That covers sharpening, hybrid images that change as you step back, and seams that disappear because each frequency band gets its own blend width.

    PART 2.1Image “Sharpening”

    A Gaussian keeps the low frequencies. Subtract that from the image and what's left is the detail. Add some extra detail back and the picture looks sharper. None of this adds information, and later in this section I measure how far the trick actually gets.

    From “blur, subtract, add” to one kernel

    Let $f$ be the image and $G_\sigma$ a normalised Gaussian. The blurred image $f * G$ is the low-pass part, so $f - f*G$ is the high-pass part (edges, texture, noise). Unsharp masking adds $\alpha$ copies of that detail back:

    $$f_{\text{sharp}} = f + \alpha\,(f - f*G) = f*\delta + \alpha\,(f*\delta - f*G) = f * \underbrace{\big((1+\alpha)\,\delta - \alpha\,G\big)}_{\text{unsharp mask kernel}}$$

    Convolution is linear, so the three steps collapse into one kernel: a tall positive spike of height $1+\alpha$ sitting in a shallow negative Gaussian “moat” of total weight $-\alpha$. The weights still sum to $1$, so flat regions don't change. Only places where the image differs from its neighbourhood get pushed further away from it.

    In frequency space the kernel's transfer function is $\;1 + \alpha\big(1 - \hat G(f)\big)$, with $\hat G(f) = e^{-2\pi^2\sigma^2 f^2}$: gain $1$ at DC, rising smoothly to $1+\alpha$ for frequencies well above the Gaussian's cutoff. It is a high-shelf filter, the same thing as the treble knob on a stereo.

    Why it can't fully work: the spectrum

    Where halos come from

    Observations

    1. Sharpening ≠ restoring. Unsharp masking makes the blurred tiger look sharper and does improve both metrics (up to 27.34 dB and SSIM 0.812), but the fine fur texture is gone for good. The blur multiplied those frequencies by $e^{-2\pi^2\sigma^2 f^2} \approx 0$, and multiplying by a finite gain afterwards can't bring back what is essentially zero.

    2. More is not better. Past the peak, PSNR drops below that of the blurry input (α = 8 with σ = 2: 20.81 dB). Halos and amplified noise count as errors, even though to a casual viewer the over-sharpened image may look more detailed.

    3. Knowing the blur helps a lot. Wiener deconvolution divides by the blur's actual transfer function and backs off where noise dominates. That buys another +1.71 dB on top of the best unsharp mask. (I picked its regulariser $K$ = 3.00e-04 by PSNR against ground truth, which is an oracle choice. A real deblurrer would have to estimate both $K$ and the kernel.)

    Deep dive: the Wiener filter I compared against

    If the blurry image is $g = f * h + n$, the linear filter minimising $\mathbb E\|f - \hat f\|^2$ is, in frequency space,

    $$\hat F(\omega) = \frac{H^*(\omega)}{|H(\omega)|^2 + K}\, G(\omega),$$

    where $K$ approximates the noise-to-signal power ratio. Where $|H|^2 \gg K$ this inverts the blur exactly. Where the blur has wiped a frequency out ($|H|^2 \ll K$) it gently returns zero instead of dividing by nearly zero and blowing up the noise. Unsharp masking, by comparison, is a fixed guess at $1/H$ that doesn't account for either the actual blur or the noise.

    def wiener_deconvolve(img: np.ndarray, sigma: float, k: float) -> np.ndarray:
    """Frequency-domain inverse of a KNOWN Gaussian blur, regularised by k (noise-to-signal).
    Reflect-pads first so the FFT's circular assumption doesn't wrap edges around."""
    if img.ndim == 3:
        return np.stack([wiener_deconvolve(img[..., c], sigma, k) for c in range(3)], -1)

    p = G.shape[0]

    PART 2.2Hybrid Images

    The idea comes from Oliva, Torralba & Schyns (SIGGRAPH 2006). When you're close to a picture, the fine detail dominates what you see. From farther away that detail gets too small to resolve and only the coarse layout is left. So if I put one picture's coarse layout and another picture's fine detail into the same image, you'll see a different picture depending on how far away you stand. Try the 🚶 walk away buttons below.

    The recipe

    $$H \;=\; \underbrace{I_1 * G_{\sigma_1}}_{\text{low-pass: seen from afar}} \;+\; \underbrace{\big(I_2 - I_2 * G_{\sigma_2}\big)}_{\text{high-pass: seen up close}}$$

    A Gaussian with standard deviation $\sigma$ pixels has frequency response $\hat G(f) = e^{-2\pi^2\sigma^2 f^2}$ ($f$ in cycles/pixel), so its half-amplitude cutoff is

    $$f_{50} = \frac{1}{\pi\sigma}\sqrt{\tfrac{\ln 2}{2}} \;\approx\; \frac{0.187}{\sigma}\ \text{cycles/pixel} \;=\; \frac{0.187\,N}{\sigma}\ \text{cycles per image}$$

    for an $N$-pixel-wide image. That is how every σ on this page converts to “cycles per image”. The paper found the useful range for the two cutoffs to be a few cycles per image up to a few tens, with some separation between them. When they overlap, both images compete at the same scale and you just see a double exposure.

    Alignment

    The two images need to line up, or the high frequencies of one won't sit on the matching features of the other and the brain won't fuse them. I pick two landmarks per image (the pupils) and solve for the similarity transform (rotation + uniform scale + translation) that moves them to fixed spots on a shared canvas. Rotation comes from normalised dot and cross products, so no trig function is needed. I also warp an all-ones image with the same transform and check that 0.0 % of the canvas falls outside the source photo for every face pair, so there are no mirrored or black borders for the high-pass to turn into bright fake edges. For the Earth and Moon there are no eyes, so I threshold the disc, take its centroid, and get the radius from its area as $r=\sqrt{A/\pi}$.

    def band_energy(img, sigma_low, sigma_high):
    """RMS of luminance (L*) and chroma (a*, b*) in the band each half of the hybrid keeps.
    Low band = blur(x, sigma_low) minus its mean; high band = x - blur(x, sigma_high)."""
    lab = rgb2lab(np.clip(img, 0, 1))

        x = lab[..., ch]
        lo = blur(x, sigma_low).reshape(x.shape)
        lo = lo - lo.mean(axis=(0, 1))
        hi = x - blur(x, sigma_high).reshape(x.shape)

                         total=float(np.sqrt((tot ** 2).sum(-1).mean())),
                         dc=float(np.sqrt((x.mean(axis=(0, 1)) ** 2).sum())))

    PART 2.3Gaussian and Laplacian Stacks

    A pyramid halves the image at every level. A stack keeps every level at full resolution and gets its "coarseness" purely from blur. You trade memory for simplicity: every level lines up pixel-for-pixel with the original, so a mask, a crop or a plot is the same at every scale. No resampling, no off-by-one, no aliasing.

    The recipe, with $g_\sigma$ a Gaussian of standard deviation $\sigma$:

    $$G_0 = I,\qquad G_{i+1} = G_i * g_{\sigma_0 2^{i}},\qquad L_i = G_i - G_{i+1}\ (i<N),\qquad L_N = G_N.$$

    The blur added at step $i$ doubles each time ($\sigma_0 2^i$ = 1, 2, 4, 8, 16 px here). Variances add under convolution, so level $i$ has an effective blur of $\sqrt{\sum_{j<i}(\sigma_0 2^j)^2}$: 0, 1, 2.2, 4.6, 9.2 and 18.5 px. That is roughly one octave per level, the same spacing a pyramid gets from its factor-of-two downsampling. Since the last entry is the low-pass residual, the sum telescopes:

    $$\sum_{i=0}^{N} L_i = (G_0 - G_1) + (G_1 - G_2) + \dots + (G_{N-1} - G_N) + G_N = G_0 = I .$$

    def gaussian_stack(img: np.ndarray, levels: int, sigma: float = 2.0, double: bool = True) -> list[np.ndarray]:
    """levels+1 images, all full resolution.

    With double=True the blur applied at step i is sigma * 2**i, so the effective scale of
    level i grows ~2x per level -- the same band structure a pyramid gets from its
    downsampling, but without throwing pixels away. With double=False every step uses the
    same sigma (effective sigma grows only like sqrt(i)).
    """
    out = [img.astype(np.float64)]
    for i in range(levels):
        s = sigma * (2 ** i) if double else sigma
        out.append(blur(out[-1], s))
    return out

    def laplacian_stack(img: np.ndarray, levels: int, sigma: float = 2.0, double: bool = True) -> list[np.ndarray]:
    """L_i = G_i - G_{i+1}; the last entry is the residual low-pass G_N, so sum(L) == img exactly."""
    g = gaussian_stack(img, levels, sigma, double)
    return [g[i] - g[i + 1] for i in range(levels)] + [g[-1]]

    What each level actually is

    To see which frequencies a level keeps, I push an impulse through the stack and take the Fourier transform of each Laplacian level. That gives the band's transfer function directly. Each curve is an octave-wide band-pass, the peaks sit about a factor of two apart, and the dashed sum is flat at 1 (off by at most 1.8e-04, from truncating the Gaussian kernels). Nothing is lost, nothing is double-counted.

    The mask gets the same treatment. Its Gaussian stack $GM_i$ widens the seam level by level. Section 2.4 builds on that.

    Takeaway

    Stacks and pyramids hold the same bands. The pyramid just stores the coarse ones at a sample rate that matches their bandwidth. Throwing samples away makes a pyramid compact. Keeping them all makes a stack easy to reason about, and every level can be looked at, masked or plotted without resizing anything.

    PART 2.4Multiresolution Blending (a.k.a. the Oraple)

    Burt and Adelson's point (1983) is that a seam's width should depend on the frequency. Coarse structure, like the overall colour of a fruit, needs a wide, gentle transition, or you see a step. Fine structure, like pores and specular speckle, needs a narrow one, or you see two textures on top of each other. One crossfade can't do both. A Laplacian stack gives a separate crossfade to every band.

    $$LS_i = GM_i\,LA_i + (1-GM_i)\,LB_i,\qquad \text{result} = \sum_{i=0}^{N} LS_i$$

    $LA, LB$ are the Laplacian stacks of the two images and $GM$ is the Gaussian stack of the mask. The mask's stack is what makes the stack version work. With pyramids, the down/up-sampling blurs a sharp seam on its own. A stack never resamples, so if you use a sharp mask at every level (the algorithm on p. 226 of the paper) you get a result that is exactly the hard cut. I checked: the max difference is 1.1e-16, pure round-off. Blurring the mask with its own stack (p. 230) is what widens the seam band by band.

    slop/blend.py · multires_blend()
    def multires_blend(A, B, mask, levels=6, sigma=2.0, mask_sigma=None, return_stacks=False):
    """Blend A (where mask=1) with B (mask=0) band by band.

    LS_i = GM_i * LA_i + (1 - GM_i) * LB_i ,  result = sum_i LS_i
    The mask gets its own Gaussian stack, so coarse bands see a wide soft seam and
    fine bands see a sharp one -- exactly the point of the 1983 paper.
    """
    LA = laplacian_stack(A, levels, sigma)
    LB = laplacian_stack(B, levels, sigma)
    GM = gaussian_stack(mask.astype(np.float64), levels, mask_sigma or sigma)
    LS = []
    for la, lb, gm in zip(LA, LB, GM):
        gm = _expand_mask(gm, la)
        LS.append(gm * la + (1 - gm) * lb)
    out = np.sum(LS, axis=0)
    if return_stacks:
        return out, dict(LA=LA, LB=LB, GM=GM, LS=LS)
    return out

    The oraple

    Why not just feather?

    A feathered blend uses one mask blur for every frequency. A narrow feather is fine for the pores but leaves a visible colour step. A wide feather fixes the colour but crossfades the orange's pores over dozens of pixels of apple skin, so you get a double exposure:

    methodseam gradient ÷ mean gradientwhat you see
    hard cut7.38a knife line
    Laplacian pyramid (mine)1.71seamless
    Laplacian stack1.55seamless, pores intact
    feather σ = 81.13smooth, but slightly ghosted pores
    reference: apple alone1.17no seam at all

    The metric is the mean horizontal luminance gradient in the two columns at the seam, divided by the image's mean gradient. A value near 1 means the seam columns look like any other columns. The feather scores lowest, and that shows the metric's limit: blurring always lowers gradients, and ghosting is not a gradient. The transition-width plot and the zooms above capture what this number can't.

    def disc_geometry(img: np.ndarray, thresh: float = 0.08):
    """Centre and radius of the bright disc (planet / moon) on a black background."""
    m = img.mean(2) > thresh
    m = ndi.binary_fill_holes(ndi.binary_opening(m, iterations=3))
    lab, n = ndi.label(m)
    sizes = ndi.sum(m, lab, range(1, n + 1))
    m = lab == (np.argmax(sizes) + 1)
    ys, xs = np.nonzero(m)
    return (xs.min() + xs.max()) / 2, (ys.min() + ys.max()) / 2, (xs.max() - xs.min() + ys.max() - ys.min()) / 4

    Irregular mask #1: a Starry Night over Sather Tower

    The mask is computed, not hand-drawn. Sky pixels are blue-dominant ($B > R + 0.08$, $B > G$), have a hue between 190° and 240°, and are bright ($V > 0.45$). I keep only the connected components that touch the top row, because the sky is above everything, and that removes blue windows and cars. A morphological close, fill-holes and open then remove leaf-sized speckle. The result covers 43.0% of the photo. The sky itself comes from the painting: I crop it to the right of the cypress and above the hills, and stretch it by 1.1× vertically (brush strokes don't mind) so it covers the photo's sky.

    parts/p2_4_blend.py · sky_mask()
    def sky_mask(img: np.ndarray) -> np.ndarray:
    """Automatic sky segmentation: 'blue, bright, and connected to the top edge'.

    1. colour test in RGB + HSV: blue channel dominates, hue in the sky-blue range, not dark;
    2. keep only connected components that touch row 0 (sky is above everything);
    3. morphological close -> fill holes -> open, to remove leaf-sized speckle.
    """
    u8 = (np.clip(img, 0, 1) * 255).astype(np.uint8)
    hsv = cv2.cvtColor(u8, cv2.COLOR_RGB2HSV).astype(np.float64)
    hue, val = hsv[..., 0] * 2, hsv[..., 2] / 255
    r, g, b = img[..., 0], img[..., 1], img[..., 2]
    blue = (b > r + 0.08) & (b > g) & (hue > 190) & (hue < 240) & (val > 0.45)
    lab, _ = ndi.label(blue)
    touching_top = [k for k in np.unique(lab[0]) if k != 0]
    sky = np.isin(lab, touching_top)
    sky = ndi.binary_closing(sky, iterations=2)
    sky = ndi.binary_fill_holes(sky)
    sky = ndi.binary_opening(sky, iterations=2)
    return sky.astype(np.float64)

    PART 2.4 · BELLS & WHISTLESColour in Multiresolution Blending

    Every blend above runs the stack on each RGB channel separately. The question here is how colour should be blended. Does it need the multiresolution treatment at all, and should it use the same seam widths as brightness?

    I tried five variants on two very different seams: the oraple (an artificial cut through two similar objects) and the Starry Campanile (a mask that follows a real object boundary):

    First surprise: RGB and Lab give the same result when both use the same stack (mean difference under 0.001 on a 0–1 scale). The blend is a per-band linear combination with weights that sum to one. Lab is a nonlinear space, but it is smooth enough that a convex mix in Lab lands where the RGB mix would. The colour space turns out not to matter. What matters is how wide the chroma seam is compared to the luminance seam.

    The oraple: colour needs a soft seam

    Why does the wide-chroma apple get duller? Its apple-side colour moves from (a*, b*) = (24.1, 43.4) to (17.3, 33.0). The extra-wide chroma levels reach so far past the seam that they pull in the colour of the orange's hidden left half. That half is in shadow and nearly grey (a* ≈ 3, b* ≈ 7), so the apple gets desaturated by an orange you never see. A hard cut is too narrow, and a very wide seam lets in colour from regions the mask is meant to exclude.

    Verdict

    Colour clearly helps: the grey versions lose the idea of each blend entirely (a grey oraple is just two bumpy spheres). How to blend it depends on the seam. Along an invented seam through similar objects (the oraple, the Moorth), blend chroma with the same stack as luminance. A hard cut leaves a hue line, and a very wide seam pulls in colour from the hidden half. Along a real object boundary (sky vs. trees), blend luminance with the stack and let chroma follow the mask closely. Human vision has coarse chroma resolution, but it is very good at noticing colour that has leaked onto the wrong object.

    CODAThe most important thing I learned

    One Gaussian does almost all of the work in this project. Every part is a decision about which frequency band goes where.

    The derivative of Gaussian is a band-pass filter, and it finds edges because it ignores the frequencies where the noise lives. Unsharp masking is $(1+\alpha)\delta - \alpha G$: an impulse minus a Gaussian, with the high band turned up. A hybrid image assigns the low band to one picture and the high band to another, and your visual system decides which one you see by how far away you stand. A Laplacian stack is a set of Gaussians subtracted pairwise, and multiresolution blending works because each band gets a seam about as wide as its own wavelength. Once I saw that, I stopped treating these as five separate tricks. They are one idea (an image is a sum of frequency bands, and a convolution chooses which bands to keep) applied five times.

    The second lesson was more personal to how this page was made: the numbers were never enough, and I had to look at the pictures. Several times a sensible-looking default was quietly wrong, and only looking at the output showed it:

    • The course's cameraman.png has a white frame around the photo, and every derivative filter lit it up as the strongest “edge” in the image. I cropped it off before computing any gradients.
    • Otsu's method is a principled way to pick a threshold, and it chose a value that left the lawn speckled with noise. The threshold I actually used came from comparing how the lawn and the subject responded at different levels.
    • I assumed the tiger would have the most fine detail and belonged in the high band. Measured, the kitten actually has more. The tiger still goes on top, because what makes a tiger recognizable is its stripes, not its fine fur.
    • cv2.warpAffine silently ignored the border mode I asked for on float64 input and filled the edges with black. That only showed up as dark wedges in the aligned images, and never in any error metric.

    Frequency analysis tells you what an operation can do. Deciding whether it did the right thing still meant looking at the image, and even for a model that was the part where the real decisions were made.

1.1Convolutions from scratch

4 Loop convolution targeting each individual pixel, and 2 loop convolution using numpy vector operations to perform the whole operation at one time. Both versions flip the kernel first, since it would be cross correlation otherwise.

In the four loop version, the outer two loops go through every output pixel, and the inner two go through every value of the kernel and add up pixel times weight. The two loop version gets rid of the inner loops by grabbing the whole patch of the image under the kernel and having numpy multiply and sum it

Four loops

def convolution_4loop(image, kernel):
    # make sure we flip so we don't do cross correlation
    kernel = np.flip(kernel)
    image_height, image_width = image.shape
    kernel_height, kernel_width = kernel.shape

    # zero padding
    pad_rows = kernel_height - 1
    pad_cols = kernel_width - 1
    padded = np.pad(image, ((pad_rows, pad_rows), (pad_cols, pad_cols)), mode="constant")
    output_height = image_height + kernel_height - 1
    output_width = image_width + kernel_width - 1
    output = np.zeros((output_height, output_width))

    for row in range(output_height):
        for col in range(output_width):
            total = 0
            for kernel_row in range(kernel_height):
                for kernel_col in range(kernel_width):
                    pixel = padded[row + kernel_row, col + kernel_col]
                    weight = kernel[kernel_row, kernel_col]
                    total = total + pixel * weight
            output[row, col] = total

    return output

Two loops

def convolution(image, kernel):
    #conv in 2 loops
    kernel = np.flip(kernel)
    image_height, image_width = image.shape
    kernel_height, kernel_width = kernel.shape

    pad_rows = kernel_height - 1
    pad_cols = kernel_width - 1
    padded = np.pad(image, ((pad_rows, pad_rows), (pad_cols, pad_cols)), mode="constant")
    output_height = image_height + kernel_height - 1
    output_width = image_width + kernel_width - 1
    output = np.zeros((output_height, output_width))

    for row in range(output_height):
        for col in range(output_width):
            # Instead of going pixel by pixel and applying our kernel to each
            # we can grab the whole patch and use numpy vectorized operations
            window = padded[row:row + kernel_height, col:col + kernel_width]
            output[row, col] = np.sum(window * kernel)

    return output

While the same operations are performed for four loops versus two loops in the two convolutions, the two loop convolution is almost 10 times as fast, as we perform a substantial portion of the operations in numpy. Scipy is much faster than both implementations, likely due to it being implemented in C and heavily optimized.

Since we were instructed to use zero padding for this part, that means that when we slide the convolution through our image, any part of the kernel that lands outside of the source image uses zero values for those pixels. This creates an artificial dark border with our box filter. Since the box filter returns the average of pixels within its kernel, on the edges, a substantial number of those values would be 0, which correspond to black. Thus the pixels on the edges will artificially become black due to this padding. This matches scipy's convolve2d with mode="full", which also pads with zeros by default; for the rest of the project I switch to boundary="symm", which mirrors the image instead.

Results on a picture of me

The box filter blurs the image. Dx responds to vertical edges like the railing posts and the sides of my body, and Dy responds to horizontal edges like the horizon and the rails. Gray means no change, and light or dark means a change in one direction or the other.

1.2Finite difference operator

Convolving the cameraman with Dx = [1, 0, -1] and its transpose Dy gives the partial derivatives in x and y, and combining them as sqrt(dx^2 + dy^2) gives the gradient magnitude. Then we can just set a threshold for magnitudes to capture edges

For the cameraman image, I used a threshold of 0.34, which captures the edges of the figure without capturing most of the noise from the grass. This does lose a few edges within the figure. The threshold was also applied to a few of the images in the image lab, showing that this singular value does not generalize very well. Luckily, theres something we can do to improve it.

1.3Derivative of Gaussian (DoG) filter

To deal with the noise, I first blur the image with a Gaussian. I build the Gaussian with cv2.getGaussianKernel, which gives a 1D kernel, and then take an outer product with its transpose to get the 2D kernel.

def gaussian_1d(strength):
    # allow us to set the strngth and size of the gaussian
    # makes our life much easier when we use this later in part 2
    size = int(6 * strength + 1)
    if size % 2 == 0:
        size = size + 1
    return cv2.getGaussianKernel(size, strength)

def gaussian_2(strength):
    kernel_1d = gaussian_1d(strength)
    return kernel_1d @ kernel_1d.T

Blur first, then take the derivative

The blur removes the fine grass texture before the derivative ever sees it, so the gradient magnitude image is much cleaner. Because the noise is gone, I could drop the threshold from 0.34 to 0.2 without the grass coming back, which recovers edges that were lost before. The threshold also has to come down, because the blur spreads each real edge over more pixels, so its gradient is weaker and 0.34 would throw away real edges.

DoG filters

Convolution is associative, so instead of blurring the image and then taking the derivative, I can convolve the Gaussian with Dx and Dy once and use those derivative of Gaussian filters on the image with a single convolution.

Both ways give the same result: the largest difference in any pixel is about 7e-16, and the two edge images are identical.

Bells & whistles: gradient orientation

The orientation at each pixel is the angle of the vector (dx, dy), using the DoG gradients. I use np.arctan2(dy, dx) to get the angle, which I then map to a color.

def orientation_image(angle, brightness):
    hsv = np.zeros((angle.shape[0], angle.shape[1], 3))
    hsv[:, :, 0] = (angle + math.pi) / (2 * math.pi)
    hsv[:, :, 1] = np.ones(angle.shape)
    hsv[:, :, 2] = brightness
    return matplotlib.colors.hsv_to_rgb(hsv)

angle = np.arctan2(dog_gradient_y, dog_gradient_x)

orientation = orientation_image(angle, np.clip(dog_magnitude / 0.3, 0, 1))

orientation_full = orientation_image(angle, np.ones(angle.shape))

This angle goes from -pi to pi, so I rescale it to 0 to 1 and use it as the hue in HSV. Hue is a circle, which matches the fact that angles wrap around, so an angle just below pi and one just above -pi get almost the same color. With full brightness everywhere, the sky and the grass turn into colored noise, because a pixel with a tiny gradient still has an angle. So in the final version the brightness is the gradient magnitude (divided by 0.3 and clipped), which makes flat areas go dark and leaves only the real edges colored. Edges facing the same way have the same color, and the two sides of each tripod leg are opposite colors because the brightness changes in opposite directions across them.

2.1Image "sharpening"

A Gaussian blur is a low pass filter, so it keeps only the low frequencies of an image. Subtracting the blurred image from the original leaves what the blur took away, which is the high frequencies. Our image looks sharper when those are stronger, so the unsharp mask adds them back on top of the original:

sharpened = image + amount * (image - blurred)

We can make this into one filter. If e is the unit impulse (a 1 in the center and zeros everywhere else) and g is the Gaussian, the sharpened image is just the original convolved with (1 + amount) e - amount g. We are essentialy just boosting all frequencies while lowering low frequencies, resulting in our high "sharp" frequencies being boosted.

def unsharp_mask_filter(strength, amount):
    # subtract blurred version of our image from our image to get high frequencies
    kernel = -amount * gaussian_2(strength)
    center = kernel.shape[0] // 2
    kernel[center, center] += 1 + amount
    return kernel

def sharpen(image, strength, amount):
    kernel = unsharp_mask_filter(strength, amount)
    return np.clip(convolve_color(image, kernel), 0, 1)

2.2Hybrid images

Our hybrid images adds the low frequencies of one image to the high frequencies of another. Up close the high frequencies win, and from far away, or small on the screen, only the low frequencies are visible. The low pass filter is a Gaussian blur, and the high pass filter is the image minus its Gaussian blur.

To have a good looking hybrid image, you need to make sure the images align. I picked the two eyes in each photo and rotated, scaled and shifted Nutmeg so that the points from the cats eyes land on Derek's.

Cutoff frequencies were chosen pretty arbitrarily, and it was mostly just guess and check, then choose what aestheticly looked the best. 2.3Gaussian and Laplacian stacks

A Gaussian stack is the same image blurred more and more at each level, without ever downsampling like we do in our project 1 pyramids. Since the image stays the same size, I double sigma at each level instead (2, 4, 8, 16). Each level of the Laplacian stack is the difference between two neighboring Gaussian levels, so it holds one band of frequencies. The last Laplacian level is just the last Gaussian level, so adding up the whole Laplacian stack gives back the original image.

def gaussian_stack(image, levels, strength):
    # just progressively apply stronger blurs on the previous blurred image
    stack = [image]
    for level in range(1, levels):
        stack.append(blur_color(stack[level - 1], strength))
        strength = strength * 2
    return stack

def laplacian_stack(image, levels, strength):
    gaussians = gaussian_stack(image, levels, strength)
    # subtract gaussian from one further on the stack to extract the "lost details" from each level
    stack = []
    for level in range(levels - 1):
        stack.append(gaussians[level] - gaussians[level + 1])
    stack.append(gaussians[levels - 1])
    return stack

2.4Multiresolution blending

To blend two images I use a Laplacian stack for each image and a Gaussian stack for the mask. At every level the two Laplacians are combined using the mask from that level, and then all the levels are added up. The mask gets blurrier at each level, so fine detail switches from one image to the other over a narrow strip, while the overall color and brightness change over a wide one. That is what hides the seam. The mask stack is always one level blurrier than the image level it is paired with, so even the finest details switch over a soft edge instead of a hard cut.

def mask_stack(mask, levels, strength):

    gaussians = gaussian_stack(mask, levels + 1, strength)
    stack = []
    for level in range(1, levels + 1):
        stack.append(gaussians[level])
    return stack

def blend_levels(image_a, image_b, mask, levels, strength):
    laplacian_a = laplacian_stack(image_a, levels, strength)
    laplacian_b = laplacian_stack(image_b, levels, strength)
    masks = mask_stack(mask, levels, strength)
    left = []
    right = []
    combined = []

    for level in range(levels):
        left.append(masks[level] * laplacian_a[level])
        right.append((1 - masks[level]) * laplacian_b[level])
        combined.append(left[level] + right[level])
    return left, right, combined

Bells & whistles: color

All of our images for 2.4 support color. In the LeCun and Hinton blend, I was pretty unhappy with the color seam we were seeing. This can be by design for some images, or it could be fixed with better image choices. However, I really wanted to make this combo of LeCun and Hinton work. We know that most of the valuable color data lies in the low frequencies. So, for this image, what if I try and apply the color from Hinton to these low frequencies signals in LeCun? I make the low frequency parts of the stack for lecun equal the average brightness across Lecuns color channels + Hinton's color, which is his level subtracted by the average of the color channels. I was actually suprisingly happy with this effect. It still has a bit of a seam, but matching the colors improves it a lot, and expands the amount of pictures that work well with this blending technique when you want to minimize a seam, and care more about the high frequency features, such as facial details.

3The most important thing I learned

The most important thing from this project is that images can be split into frequencies, and its actually useful to do so. There are many advantages to viewing images in relation to their frequencies, in a way that would not be intuitive by looking at the raw pixel values. It also shows the usefulness and applicability of convolutions for digital image processing. Blending and hybrid images were fun, but I think that the relationship between high and low frequency features in images is important, especially as we move in to the machine learning portion of the course. Much of this will be features of images learned by our models, so understanding how to do this by hand will let us interpret them better.
